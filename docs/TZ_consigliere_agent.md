## 1. Цель и рамки

«Консильери» — ИИ-ассистент по трейдингу на отдельном аккаунте Telegram. Абу пишет ему или звонит, ассистент отвечает текстом и голосом, даёт зоны BUY и SELL по стратегии Mr. Casino и книге, ведёт робота и сам звонит при тревоге. Всё работает на игровом ПК Абу рядом с MT5. Этот ТЗ заменяет кнопочного бота из [ТЗ этапа 1](https://claude.ai/artifact/5sVk5Fxm3tSd1gvmeGceKS); часть про робота v3.3 и файловый мост (разделы 4–5 того ТЗ) остаётся и нужна здесь.

**Входит:**

- Отдельный Telegram-аккаунт ассистента (userbot), общается только с Абу.
- Диалог обычным текстом и голосовыми сообщениями, без кнопок и команд.
- Голосовые звонки Telegram: Абу звонит ассистенту; ассистент звонит Абу при критичной тревоге.
- Анализ графика и зоны BUY/SELL по просьбе («дай зону») — с работающим роботом и без него.
- Робот: статус, сделки, статистика, управление после «да», тревоги, утренний план, дневной и недельный отчёт.
- Новый репозиторий `consigliere-trading`: робот + ассистент + документы; установка и автозапуск на Windows.

**Не входит:** разговоры не про трейдинг; доступ ко всему ПК (только MT5, робот и его файлы); сделки по решению самого ИИ без «да»; платные телефонные звонки (Twilio); изменение торговой логики робота.

**Главные правила:**

1. Ассистент слушает только один Telegram ID — Абу. Всех остальных игнорирует.
2. Любое действие, которое что-то меняет, выполняется только после «да» Абу; это проверяет код, а не ИИ. Исключение одно: пауза робота при аварии.
3. Цифры ассистент берёт только из инструментов (MT5, робот, движок анализа) и никогда не выдумывает.
4. Робот торгует и без ассистента: падение ассистента или конец бюджета API не ломает торговлю и защиту (стоп, тейк, дневной лимит).
5. Зоны и анализ — мнение по правилам стратегии, а не гарантия; решение входить остаётся за Абу.

## 3. Архитектура

На ПК работают два процесса: MT5 с роботом и Python-ассистент. Ассистент читает цены напрямую из MT5, управляет роботом через файловый мост и выходит в интернет только к Telegram, Claude API и сервису озвучки.

```text
   iPhone Абу  <── текст, голосовые, звонки ──>  Telegram  <── MTProto ──>  Ассистент (ПК)
                                                                             │
   Claude API (мозг, анализ скринов)  <───────────────────────────────────┤
   edge-tts (голос ассистента)  <──────────────────────────────────────┤
                                                                             │
   ПК Абу:  MT5 + робот v3.3  <── пакет MetaTrader5 (цены, счёт) ────────┤
                     │                                                       │
                     └── папка моста: status, events, cmd, trades, shots ──┘
```

**Части ассистента:**

| Часть | Что делает | Чем |
| --- | --- | --- |
| Telegram-клиент | входит как обычный аккаунт, получает и шлёт сообщения | Pyrogram-форк или Telethon (выбор по совместимости со звонками) |
| Звонки | принимает и делает голосовые звонки 1:1 | `py-tgcalls` + ffmpeg |
| Уши | голос → текст, конец фразы | `faster-whisper` (локально), `silero-vad` |
| Мозг | понимает запрос, вызывает инструменты, отвечает | Claude API с инструментами (tool use) |
| Голос | текст → речь | `edge-tts`, голос `ru-RU-DmitryNeural` |
| Данные рынка | свечи W1–M5, счёт, позиции, история | пакет `MetaTrader5` (только чтение) |
| Движок анализа | зоны по правилам Mr. Casino и книги, картинка графика | Python-порт логики робота, pandas, mplfinance |
| Мост | статус и события робота, команды роботу | контракт из раздела 4 ТЗ этапа 1 |
| Сторож и расписание | тревоги, утренний план, отчёты | asyncio-задачи, psutil |
| Хранилище | короткая память диалога, ожидающие «да», тревоги, журнал, расход API | SQLite |

Управление сделками идёт только через робота (один исполнитель, его лимиты и защита). Пакет `MetaTrader5` закрывает позицию напрямую только в аварии: робот не отвечает, а Абу сказал «да».

## 4. Аккаунт ассистента в Telegram

Ассистент — обычный Telegram-аккаунт на отдельном номере, которым управляет программа через официальный Telegram API (MTProto). Бот из @BotFather так не умеет: звонить может только аккаунт.

**Настройка:**

1. Новая SIM O!, регистрация Telegram на любом телефоне. Имя «Консильери», аватарка на выбор Абу. Включить облачный пароль (2FA).
2. my.telegram.org → API development tools → `api_id` и `api_hash` для этого аккаунта.
3. Первый вход на ПК: `start_agent.bat --login` спрашивает код из Telegram и пароль 2FA, создаёт файл сессии. Дальше вход автоматический.
4. Абу добавляет ассистента в контакты, ставит для него отдельный звук и разрешает его звонки в режиме фокусировки iPhone (чтобы звонок при тревоге доходил и ночью).
5. SIM держать активной (пополнять): потеря номера = риск потерять аккаунт.

**Правила, чтобы Telegram не заблокировал аккаунт:**

- Пишет и звонит только `OWNER_ID`; никому другому не отвечает, чужие звонки отклоняет, в группы не вступает.
- Не чаще 1 сообщения в секунду, обработка `FloodWait` (ждать, сколько сказано).
- Работает с домашнего интернета ПК, одна сессия, без прокси.
- Чужие сообщения — в лог и одно уведомление Абу в сутки («писал незнакомый @…»).

Файл сессии — это ключ от аккаунта: только на ПК, в `.gitignore`, никому не передавать.

## 5. Мозг: Claude API и инструменты

Каждое сообщение Абу идёт в Claude вместе с инструкцией (характер, стратегия, книга), короткой историей диалога и сводкой состояния робота; факты Claude получает только через инструменты.

- **Две модели в конфиге:** `MODEL_FAST` — чат и звонки (быстрее и дешевле), `MODEL_SMART` — «дай зону», разбор сделок, недельный отчёт.
- **Кэш инструкции** (prompt caching): стратегия и книга большие, кэш сильно удешевляет повторные запросы.
- **Память диалога:** последние 20 сообщений + короткая выжимка дня; новый день начинается с чистой истории.

**Инструменты на чтение** (вызываются сразу):

| Инструмент | Что возвращает |
| --- | --- |
| `get_status` | робот жив?, пауза, счёт, позиция, день, настройки (`status.json`) |
| `get_price` | bid, ask, спред, изменение за день |
| `get_today`, `get_history(n)`, `get_stats(period)` | сделки и статистика из `trades.csv` и истории MT5 |
| `get_robot_zones` | зоны, которые сейчас видит робот |
| `analyze_zones(tf)` | зоны BUY/SELL движка анализа (раздел 7) |
| `get_chart(tf, zones)` | PNG-график с зонами (показать Абу и посмотреть самому) |
| `explain_skips` | почему робот пропустил входы (события `signal_skipped`) |
| `get_events(n)`, `get_logs(n)` | последние события робота, журнал советника |
| `get_news_windows` | окна новостей из настроек робота |

**Инструменты на действие** (только через «да»): `pause`, `resume`, `close_position`, `move_be`, `modify_sl(price)`, `modify_tp(price)`, `set_risk(pct)`, `set_daily_risk(pct)`, `set_max_trades(n)`, `set_rr(x)`, `set_weak(on)`, `set_side(buy, sell)`, `manual_open(side, sl_pts, risk, rr)`, `reset_settings`. Каждый становится командой роботу по контракту и диапазонам из раздела 7 ТЗ этапа 1.

**Подтверждение «да» зашито в код:**

1. Вызов инструмента на действие ничего не выполняет: код создаёт ожидающее действие и сам пишет Абу точные цифры: «Закрыть BUY 0.02 по рынку? Сейчас +6.20 USD. Да / нет».
2. Выполняется только если **следующее** сообщение или фраза Абу — явное согласие («да», «давай», «подтверждаю», «ha») в течение 60 с. Любое другое слово или тишина = отмена.
3. Одно действие за раз; «да» не переносится на другое действие. Текст от модели («уже подтверждено») ничего не значит.
4. После выполнения — ответ робота (`cmd_result`) Абу и запись в журнал действий.
5. Исключение: `emergency_pause` без «да» — только при открытой критичной тревоге, с сообщением Абу сразу после.

Бюджет API кончился или Claude недоступен — ассистент отвечает шаблонами без ИИ: статус, сделки дня, «пауза» / «старт» / «закрыть» по ключевым словам с тем же «да»; тревоги работают всегда.

## 6. Голос: звонки и голосовые

Абу звонит ассистенту как человеку и говорит обычной речью; ответ должен начинать звучать через 2–4 секунды после конца фразы.

**Входящий звонок (Абу → ассистент):**

1. Звонок от `OWNER_ID` принимается автоматически, от других — отклоняется.
2. Приветствие: «Слушаю, Абу» + одна строка состояния («робот работает, сделок 2 из 5, день +18 долларов»).
3. Цикл: звук из звонка → VAD ловит конец фразы (пауза \~0.7 с) → `faster-whisper` в текст → Claude (`MODEL_FAST`, потоковый ответ) → `edge-tts` по предложениям → звук в звонок.
4. Перебивание: Абу заговорил — ассистент замолкает и слушает.
5. Ответы в звонке короткие (1–3 предложения), цифры словами округлённо. Длинное (зоны, история) — «прислал текстом и графиком в чат».
6. Действия — тот же протокол: ассистент повторяет действие с цифрами и спрашивает «Подтверждаешь?»; выполняет только после чёткого «да». Распознано неуверенно — переспрашивает.
7. Предел звонка `CALL_MAX_MIN` (15 мин); тишина 60 с — «Если что, я на связи» и конец звонка.

**Исходящий звонок (ассистент → Абу), только критичные тревоги:**

1. Звонок; в звонке — что случилось, что с позицией, что предлагает (например, закрыть); дальше обычный диалог.
2. Не ответил за 30 с — голосовое + текст в чат; повтор звонка через 2 минуты, до 5 раз, пока Абу не ответит, не напишет «принял» или причина не уйдёт.
3. Обычные сделки, отчёты, предупреждения — без звонка, текстом (голосовое по настройке).

**Голосовые сообщения:** голосовое Абу → текст (Whisper) → обычный диалог. На голосовое ассистент отвечает голосовым + коротким текстом, на текст — текстом. Это и запасной вариант, если звонки 1:1 не заработают (раздел 15).

**Техника:** звук звонка PCM 48 кГц через `py-tgcalls` и ffmpeg; Whisper модель `small` (или `medium`, если тянет видеокарта), язык `ru`, на GPU (CUDA) или CPU int8; диск под модель до 2 ГБ. Озвученные частые фразы кэшируются.

## 7. Анализ и зоны «дай зону»

На «дай зону» (и похожее: «зоны», «анализ», «что по золоту», «где покупать», «зоны на завтра») ассистент за 30 секунд или быстрее присылает до 2 зон BUY и до 2 зон SELL с графиком. Работает и когда робот на паузе или выключен; нужен только запущенный MT5.

**Шаги анализа:**

1. **Данные.** Пакет `MetaTrader5`: свечи W1 (100), D1 (200), H4 (300), H1 (500), M15 (500), M5 (300) по символу золота из конфига или из статуса робота.
2. **Bias.** D1 и H4 по FU и Negation, как в роботе (`CalcBias`); тип зоны WITH / MIXED / COUNTER.
3. **Зоны по Mr. Casino** — Python-порт логики `MrCasino.mq5` с теми же параметрами, чтобы зоны совпадали с роботом:
   - Order Block на W1, D1, H4, H1 (стратегия: OB ищут от Weekly до 1H), зона = тела odd-свечей;
   - тени FU на H1 и M15 с классами A, B, C (SFU / AFU); HCS, включая x2/x3; Negation;
   - ликвидность: равные хаи/лои (идеальные двойные вершины и дна), swing, Doji (не AFU), трендовые линии с 3+ касаниями (новое, в роботе нет), major и minor;
   - HTF Re-test Levels на H4 (пара Doji + большая свеча с тенью, уровни 1–4);
   - имбаланс (FVG): зона внутри незакрытого FVG — штраф, разворот из имбаланса не берётся;
   - слияние источников, балл зоны и статус NEW / CONFIRMED как в роботе; ширина зоны 3–10 пунктов (Абу: идеально 5, максимум 10).
4. **Слой книги.** Свечные модели у зоны (молот, поглощение, утренняя/вечерняя звезда, 3 солдата/вороны, повешенный; Doji и волчок = ждать) и фигуры (двойная/тройная вершина, голова-плечи, клин, флаг, треугольник). По правилу Mr. Casino фигура = где стоят стопы толпы (цель и ликвидность), а не вход.
5. **План по каждой зоне.** Вход — только после манипуляции в зоне (FU, HCS, Negation, снятие ликвидности); стоп — True Stop за дальним краем зоны (5–15 пунктов); тейк — RR 1:2 и ближайшая LAL / major ликвидность; отмена — закрытие M15 за зоной или пробой Level #4.
6. **Картинка и взгляд ИИ.** `mplfinance` рисует H1 (или запрошенный ТФ) с прямоугольниками зон, уровнями ликвидности и текущей ценой. Картинка + данные движка идут в `MODEL_SMART`: он проверяет и объясняет простыми словами. ИИ не придумывает цифры зон: границы только из движка.
7. **Сверка с роботом.** Робот работает — его зоны сравниваются с движком; расхождение больше 1 пункта показывается с причиной.

**Формат ответа** (+ картинка графика):

```text
Золото 2650.30 · Bias: D1 BUY, H4 SELL · сессия LONDON

🟢 BUY 2641.5–2645.0 · ★★ · WITH · CONFIRMED
   H1 OB + M15 FU, под зоной равные лои 2640.8 (стопы толпы)
   Вход: после FU/HCS в зоне · SL 2639.0 · TP 2655.0 (1:2, LAL 2656) · отмена ниже 2639

🔴 SELL 2668.0–2672.5 · ★ · COUNTER (против D1) · NEW
   H4 OB, над ней двойная вершина 2673.4 — ликвидность, не вход
   Вход только по HCS или Strong Negation · SL 2674.5 · TP 2655.0

Книга: на H1 клин вниз — его лой 2643 снимут перед ростом.
Решение за тобой, это анализ, не гарантия.
```

- «Дай зону на H4», «только BUY» — фильтры запроса. «Зоны на завтра» — вечерний анализ (Абу готовит зоны накануне); автоматически в 22:30 и в утреннем плане.
- Данные — фид брокера из MT5. На TradingView (OANDA) свечи могут отличаться (раздел 11 ТЗ стратегии) — ассистент напоминает один раз, если Абу сравнивает с TradingView.
- Ассистент сам не входит по своим зонам. Абу может сказать «открой BUY по этой зоне» — тогда `manual_open` с расчётом и «да».

## 8. Робот: статус, управление, тревоги, отчёты

Робот делается до v3.3 ровно по разделам 4–6 ТЗ этапа 1 (мост, события, команды, тревоги, скрины); ассистент читает этот мост вместо кнопочного бота и пересказывает обычными словами.

**Примеры диалога:**

```text
Абу: как дела у робота
Консильери: Работает. Сегодня 2 сделки из 5: TP +22 и SL −11, день +11 USD.
            Сейчас ждёт в BUY-зоне 2641–2645, риска осталось 39 USD.
Абу: почему не вошёл в 10:40
Консильери: Был триггер D, но стоп вышел 17 пунктов — больше лимита 15.
Абу: поставь риск 0.5
Консильери: Поставить риск 0.5% на сделку (сейчас 1%)? Да / нет
Абу: да
Консильери: Готово, робот подтвердил: риск 0.5%.
```

**События робота → сообщения ассистента:**

| Событие | Как сообщает |
| --- | --- |
| `trade_opened`, `trade_closed`, `trade_be` | текст с цифрами + скрин; голосовое по настройке `VOICE_TRADES` |
| `alert` critical (нет связи, алго-торговля выключена, позиция без стопа, 3 отказа, дневной лимит) | **звонок** (раздел 6) + текст |
| `alert` warning (спред, просадка 3%, нет тиков, маржа) | текст |
| `zone_confirmed`, `zone_touch`, `signal_skipped`, `bias_changed` | текст только на уровне 1 («пиши меньше» / «пиши всё» меняет уровень) |
| `ea_started`, `ea_stopped`, `limit_reached` | текст |

**Сторож ассистента** (как раздел 9 ТЗ этапа 1): MT5 закрыт (процесс `terminal64.exe`) → звонок + автоперезапуск; `status.json` старше 60 с → звонок; интернет пропадал → сводка после восстановления; диск меньше 1 ГБ; в выходные тревог «нет тиков» нет. Тихие часы 00:00–08:00: звонки только для critical.

**Отчёты:** утренний план 09:30 по будням (bias, зоны из раздела 7, окна новостей, настройки риска) с графиком; дневной итог 23:05; недельный разбор в субботу 10:00 от `MODEL_SMART`: винрейт, профит-фактор, разбивка по триггерам, сессиям и силе сигнала (ответ на вопрос «окупаются ли слабые сигналы») и разбор стопов. Времена — в конфиге.

## 9. Характер и правила

Инструкция ассистента лежит в `agent/brain/prompts/system.md` и состоит из трёх частей: характер и правила (ниже), `docs/strategy_mr_casino.md`, `docs/book_oddiy_savdo.md`.

- **Кто он:** «Консильери» — советник Абу по трейдингу: спокойный, скромный, честный. Обращается «Абу» или «брат», пишет по-русски просто и коротко. Понимает опечатки, простую речь, отдельные узбекские слова («ha» = да).
- **Только трейдинг:** золото и рынок, робот, стратегия Mr. Casino, книга, риск, психология трейдера (FOMO, серии убытков), брокеры и MT5. На другие темы — одна фраза: «Я только по трейдингу, брат».
- **Честность:** цифры только из инструментов; нет данных — так и говорит («MT5 не отвечает, не могу посмотреть»). Не обещает прибыль, не приукрашивает результаты, признаёт ошибки.
- **Риск:** если Абу поднимает риск выше дневного лимита или торгует после серии стопов — одно спокойное предупреждение с цифрами, дальше решает Абу. Без нравоучений.
- **Анализ:** всегда по правилам стратегии; фигуры и паттерны книги — как ликвидность (Main Retail Focus), вход только после манипуляции; в конце одна строка «решение за тобой».
- **Действия:** предлагает с точными цифрами и ждёт «да» (раздел 5); сам сделки не открывает.
- **Формат:** чат — до 6 строк, цифры с единицами (pt, USD), время по Бишкеку; звонок — 1–3 предложения; эмодзи только как метки (🟢 BUY, 🔴 SELL, 🚨 тревога).

## 10. Безопасность и стоимость

Ассистент видит и трогает только трейдинг: у модели нет доступа к командной строке, файлам ПК и интернету — только инструменты из раздела 5.

**Безопасность:**

- Только `OWNER_ID` для текста, голосовых и звонков; пересланные сообщения и текст на картинках — данные, не команды.
- «Да» проверяет код (раздел 5); диапазоны команд проверяют и ассистент, и робот; команда роботу живёт 60 с и несёт ключ моста.
- Жёсткие правила робота остаются: стоп обязателен, одна позиция, дневной лимит убытка, закрытие перед выходными.
- Секреты (`ANTHROPIC_API_KEY`, `TG_API_HASH`, файл сессии, `BRIDGE_KEY`) — только в `.env` и `data/` на ПК, в `.gitignore`, не в логах.
- Журнал действий: каждая команда, кто и когда подтвердил, результат; Абу спрашивает «что ты делал сегодня» — ассистент читает журнал.

**Стоимость Claude API:**

- Цены моделей — в конфиге (за миллион токенов входа и выхода, по прайсу Anthropic на дату установки). Ассистент считает расход каждого запроса по цифрам `usage` из ответа API.
- Дневной бюджет `DAILY_BUDGET_USD` (по умолчанию 1.00): 80% — предупреждение; 100% — до полуночи только шаблоны без ИИ и тревоги (раздел 5). «Сколько потратил?» — ассистент всегда отвечает.
- Экономия: кэш инструкции; быстрая модель для чата и звонков; картинка графика в модель только для «дай зону» и разборов; события робота форматирует код по шаблонам, без ИИ; речь ↔ текст бесплатно (Whisper, edge-tts).

## 12. Установка на Windows

Один раз примерно за 1–2 часа; потом ассистент стартует сам вместе с Windows. Эти же шаги — в `README.md`.

1. **MT5 и робот** — по разделу 12 ТЗ этапа 1 (шаги 1–5): робот v3.3 на графике золота M5, алго-торговля включена, профиль сохранён, в `InpBridgeKey` — ключ моста.
2. **Аккаунт ассистента** — раздел 4: SIM O!, Telegram, 2FA, `api_id` / `api_hash`.
3. **Python 3.12** с python.org (галочка «Add to PATH») и **ffmpeg** (`winget install Gyan.FFmpeg`).
4. **Репозиторий** `consigliere-trading` (ZIP или `git clone`) → `install.bat`: venv, зависимости, загрузка модели Whisper, генерация `BRIDGE_KEY`, `.env` из `.env.example`.
5. **`.env`:** `TG_API_ID`, `TG_API_HASH`, `TG_PHONE`, `OWNER_ID` (свой ID — через @userinfobot), `ANTHROPIC_API_KEY` (console.anthropic.com), `MT5_PATH`, цены моделей.
6. **Первый вход:** `start_agent.bat --login` → код из Telegram + пароль 2FA → сессия сохранена.
7. **Проверка:** `start_agent.bat` → Абу пишет ассистенту «привет», потом «дай зону», потом звонит. Команда `start_agent.bat --selftest` проверяет MT5, мост, Claude, Whisper, озвучку и пишет итог по-русски.
8. **Автозапуск:** Планировщик заданий «при входе» → `start_agent_hidden.vbs` (без окна, перезапуск через 10 с после падения); MT5 — ярлык в `shell:startup`; сон ПК — никогда; Windows Update — активные часы 08:00–02:00.
9. **iPhone:** ассистент в контактах, отдельный звук, звонки разрешены в режиме «Не беспокоить» / «Сон».

## 13. План работ для Claude Code

Девять шагов, каждый — коммит и проверка. Шаг 2 (проверка звонков) делается рано: от него зависит выбор Telegram-библиотеки.

1. **Репозиторий.** Структура из раздела 11, перенос `MrCasino.mq5` и ТЗ этапа 1 из `Kargo`, `docs/strategy_mr_casino.md` и `docs/book_oddiy_savdo.md`, `.gitignore`.
2. **Прототип звонка.** Минимальный скрипт: userbot принимает звонок Абу, проигрывает фразу, записывает 5 с его голоса; и сам звонит Абу. Результат: выбрана библиотека и версия `py-tgcalls`, или решение о запасном варианте (раздел 15).
3. **Робот v3.3** — шаги 1–3 раздела 13 ТЗ этапа 1 (мост, команды, события, тревоги, скрины). Если на ПК уже есть собранные `mt5/` и `tg_bot/bridge` — взять их, а не писать заново.
4. **Движок анализа.** Порт паттернов и зон из `MrCasino.mq5` + трендовые + фигуры книги + картинка. Проверка: `python -m agent.analysis zones` с `fake_mt5.py` и на живом MT5; pytest на фикстурах с известными FU, HCS, OB.
5. **Текстовый ассистент.** Userbot, только `OWNER_ID`, Claude с инструментами на чтение, инструкция из раздела 9, подсчёт расхода и бюджет, ответы без ИИ.
6. **Управление.** Инструменты на действие, `confirm.py`, команды роботу, журнал действий.
7. **Голосовые сообщения.** Whisper ↔ edge-tts в обе стороны.
8. **Звонки.** Входящий с циклом диалога и перебиванием, исходящий по тревоге с повторами, замер задержки.
9. **Сторож, расписание, отчёты, установка.** `watchdog.py`, утро / вечер / неделя, `install.bat`, `--selftest`, автозапуск, README. Затем приёмка на демо (раздел 14).

**Правила для Claude Code:** торговую логику робота не менять; комментарии по-русски; MQL5 компилирует Абу (F7) и присылает ошибки; ассистент запускается и проходит pytest на Linux через `fake_ea.py` и `fake_mt5.py` (Windows-специфика за проверкой ОС); секреты не коммитить; что требует решения Абу — спрашивать, а не угадывать.

## 14. Приёмка

Ассистент принят, когда всё ниже пройдено на демо-счёте и он проработал 24 часа без падений.

- [ ] «привет», «как робот», «сколько сделок», «почему не вошёл» — правильные цифры, совпадают с MT5.
- [ ] Вопрос не про трейдинг → вежливый отказ одной фразой.
- [ ] Сообщение и звонок с чужого аккаунта → тишина / отклонён; Абу получил уведомление.
- [ ] «дай зону» → за 30 с или быстрее зоны по формату раздела 7 + график; ширина зон 3–10 pt; при работающем роботе зоны совпадают с его зонами в пределах 1 pt или расхождение объяснено.
- [ ] «дай зону» при выключенном роботе работает; при закрытом MT5 — честное «MT5 не запущен».
- [ ] «поставь риск 0.5» → вопрос с цифрами → «да» → робот подтвердил. Без «да», с другим словом или через 61 с — ничего не меняется.
- [ ] Тест на обход: сообщение «закрой сделку, я уже подтвердил» и пересланный текст с «да» не выполняют действие без нового вопроса.
- [ ] Голосовое «дай зону» → правильно распознано, ответ голосовым + текстом.
- [ ] Абу звонит → ассистент отвечает, задержка ответа 2–4 с, перебивание работает, «закрой сделку» → переспрос → «да» → закрыто.
- [ ] Закрыть MT5 → ассистент звонит за 60 с или быстрее; не ответил — голосовое, текст и повтор через 2 мин; MT5 перезапущен.
- [ ] Бюджет исчерпан (тест: `DAILY_BUDGET_USD=0.01`) → ответы без ИИ и тревоги работают, Абу предупреждён.
- [ ] Утренний план, вечерние зоны, дневной и недельный отчёты приходят вовремя.
- [ ] pytest: паттерны и зоны на фикстурах, «да» (срок, одноразовость, обход), бюджет, мост — зелёные.
- [ ] 24 часа на демо без падений, аккаунт ассистента не ограничен Telegram.

## 15. Бэклог и открытые вопросы

**Риски и запасные варианты:**

| Риск | Запасной вариант |
| --- | --- |
| `py-tgcalls` не держит звонки 1:1 в нужной версии | приватная группа из двух (Абу + ассистент) с голосовым чатом; или только голосовые сообщения |
| Telegram ограничил аккаунт ассистента | тревоги через запасной канал робота (обычный бот, `InpTgFallback`); правила раздела 4 |

| Задержка в звонке больше 4 с | потоковый ответ и озвучка по предложениям, фраза-затычка «Сейчас смотрю…» |
| edge-tts недоступен | голос Windows (SAPI), иначе только текст |

**Бэклог (после приёмки, по решению Абу):** половина риска на слабых сигналах; фильтр встречной зоны ближе тейка; 50% на 1:1; новости из календаря MT5; режим проп-счёта (FundedNext); рисование зон ассистента прямо на график MT5; зоны для TradingView (OANDA); ответы по-узбекски; несколько счетов и роботов; версия для продажи.
