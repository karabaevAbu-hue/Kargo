## 1. Цель и рамки

Этап 1 даёт бесплатную связку «робот MT5 → Telegram → iPhone»: робот сообщает обо всём, что делает, а владелец управляет им кнопками из Telegram. Всё работает на домашнем игровом ПК под Windows, без платных сервисов.

**Входит:**

- Доработка робота MrCasino.mq5 до v3.3: файловый мост, таймер, события, приём команд, сохранение настроек, скрины графика, тревоги.
- Python-бот в Telegram на том же ПК: уведомления, меню, команды, подтверждение «Да / Нет», история и статистика.
- Сторож: следит за MT5, роботом, связью, просадкой; тревоги текстом и голосовыми, с повтором до кнопки «Принял».
- Скрипты установки и автозапуска на Windows, инструкция для владельца, тесты и симулятор робота для проверки без MT5.

**Не входит** (раздел 15): Claude API («Жарвис»), распознавание голоса владельца, настоящие звонки (Twilio), VPS, изменение торговой логики стратегии.

**Главные правила:**

1. Ботом пользуется и управляет только владелец — один Telegram ID.
2. Любое действие, которое что-то меняет, выполняется только после кнопки «Да».
3. Робот торгует и без бота: если бот упал, торговля и защита (стоп, тейк, дневной лимит) работают как раньше.
4. Ничто не тормозит торговый поток робота: в OnTick нет сетевых запросов и ожиданий.

## 3. Архитектура

Робот и бот работают на одном ПК и общаются только через файлы; в интернет каждый ходит своим путём: MT5 — к брокеру, бот — в Telegram.

```text
 Брокер (Exness / XM)        Telegram  <------------------->  iPhone
        ^                       ^   ^                        (сообщения, голосовые,
        | заявки, котировки     |   :  запасной канал         кнопки «Да / Нет»)
        v                       |   :  (робот шлёт сам,
 +------ Игровой ПК · Windows --|---:--- если бот молчит > 3 мин) ------+
 |  MT5 + робот v3.3 ...........|...:                                    |
 |  (торгует, пишет события,    v                                        |
 |   выполняет команды)       Python-бот (уведомления, команды с «Да»,   |
 |        ^                   сторож и голосовые; следит за MT5)         |
 |        | пишет события,          ^ читает события;                    |
 |        v читает команды          v пишет команды                      |
 |  [ Папка моста: Common\Files\MrCasino\<login>_<magic>\ ]            |
 |    робот -> бот: status.json, events, trades.csv, shots               |
 |    бот -> робот: cmd, bot_heartbeat · робот: settings.json            |
 +-----------------------------------------------------------------------+
```

Пунктир — запасной канал: если бот молчит больше 3 минут, робот шлёт критичные события в Telegram сам. Сторож бота следит за процессом MT5 и перезапускает его.

## 4. Файловый мост

Робот и бот обмениваются только файлами в общей папке MT5; сети между ними нет. Корень: `%APPDATA%\MetaQuotes\Terminal\Common\Files\MrCasino\<login>_<magic>\` (в MQL5 — флаг `FILE_COMMON`, путь `MrCasino\\<login>_<magic>\\...`). Одна папка на каждый запущенный робот: демо и реальный счёт на одном ПК не путаются.

| Файл | Пишет | Читает | Зачем | Как пишется |
| --- | --- | --- | --- | --- |
| `status.json` | робот | бот | текущее состояние; каждые 10 с и после каждого события | `status.tmp`, затем `FileMove` с `FILE_REWRITE` (атомарно) |
| `events\YYYYMMDD.jsonl` | робот | бот | лента событий, одна строка JSON на событие, файл на день по Бишкеку | дозапись в конец |
| `cmd\<id>.json` | бот | робот | одна команда = один файл | бот пишет `<id>.tmp` и переименовывает в `.json`; робот выполняет и удаляет |
| `settings.json` | робот | робот, бот | настройки, изменённые из Telegram, и счётчик `seq`; переживают перезапуск | атомарно |
| `trades.csv` | робот | бот | закрытые сделки (колонки — раздел 10) | дозапись |
| `shots\<seq>.png` | робот | бот | скрин графика к событию | `ChartScreenShot` в `MQL5\Files`, затем `FileMove` в общую папку |
| `bot_heartbeat.json` | бот | робот | бот жив: время последнего цикла, каждые 10 с | атомарно |

**Правила формата:**

- Кодировка UTF-8 без BOM. В MQL5 писать через `FILE_BIN` + `StringToCharArray(..., CP_UTF8)`: режим `FILE_TXT | FILE_ANSI` портит русский текст.
- У каждого события и статуса есть `ts_utc` (ISO 8601 с Z) и `ts_local` (Бишкек).
- Событие: `{"seq":1532,"ts_utc":"...","ts_local":"...","type":"trade_opened","level":0,"severity":"info","robot":"<login>_<magic>","data":{...},"text":"готовый текст на русском"}`. `seq` растёт всегда и хранится в `settings.json`; `text` — запасной текст, если у бота нет шаблона на этот тип.
- Бот хранит курсор (файл, смещение в байтах, последний `seq`) в своей базе: после перезапуска не шлёт старое повторно; пропуск `seq` пишет в лог. Неполную последнюю строку (без `\n`) не читает, ждёт следующего цикла.
- При первом запуске бот начинает с конца текущего файла, а не с начала истории.
- Команда: `{"id":"<uuid>","cmd":"set_risk","args":{"pct":0.5},"ts_utc":"...","expires_utc":"<+60 с>","key":"<BRIDGE_KEY>"}`. Робот отвечает событием `cmd_result` с тем же `id`: `{"id":"...","ok":true,"msg":"риск 0.5% на сделку"}`.
- Хранение: события 30 дней, скрины 7 дней (чистит бот). Команду с истёкшим `expires_utc` робот не выполняет: удаляет и отвечает `ok:false, msg:"команда устарела"`.

Пример `status.json` (`position` = `null`, если сделки нет):

## 5. Изменения в роботе (v3.3)

Робот v3.3 получает мост, таймер, команды и тревоги; входы, стопы, тейки и фильтры v3.2 не меняются. `#property version "3.30"`, на панели — «v3.3».

### 5.1 Новые входные параметры (группа «Telegram-бот (мост)»)

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `InpBridge` | true | вести файловый мост |
| `InpBridgeKey` | "" | секрет команд; пусто = команды не принимаются, в журнал и на панель — предупреждение |
| `InpStatusSec` | 10 | как часто обновлять `status.json`, секунд |
| `InpShots` | true | скрины графика к входу, выходу, отчёту, брифингу и по команде |
| `InpShotW`, `InpShotH` | 1280, 720 | размер скрина, пикселей |
| `InpMorningHM` | "09:30" | утренний брифинг, время Бишкека (пусто = выкл.) |
| `InpReportHM` | "23:05" | дневной отчёт, время Бишкека (пусто = выкл.) |
| `InpTgFallback` | true | бот молчит дольше 3 минут — критичные события идут напрямую через `WebRequest` (нужны `InpTgToken`, `InpTgChatId` и разрешённый URL) |
| `InpAlertDDPct` | 3.0 | тревога: эквити ниже баланса начала дня на N% |
| `InpAlertSpreadX` | 3.0 | тревога: спред больше N × `InpMaxSpreadPt` дольше 2 минут при открытой позиции |

При работающем боте `InpTgToken` и `InpTgChatId` нужны только для запасного канала: в обычном режиме робот в Telegram не пишет, чтобы не было дублей.

### 5.2 Таймер

- `EventSetTimer(1)` в `OnInit`, `EventKillTimer()` в `OnDeinit`. `OnTimer` работает и без тиков (выходные, тихий рынок), поэтому команды и статус идут через него.
- Каждую секунду: проверить папку `cmd` (`FileFindFirst` с `FILE_COMMON`), выполнить команды по порядку `ts_utc`.
- Каждые `InpStatusSec`: записать `status.json`, прочитать `bot_heartbeat.json`.
- Каждые 5 с: проверить условия тревог (5.8).
- По времени Бишкека: утренний брифинг и дневной отчёт, один раз в день (дата последней отправки хранится в `settings.json`). В субботу и воскресенье брифинг не шлётся.

### 5.3 События вместо прямого Telegram

- Новая функция `Emit(type, level, severity, dataJson, text)`: пишет событие в `events`, обновляет `status.json`, оставляет Push MT5 как сейчас. `Notify()` вызывает `Emit()`.
- Прямая отправка `SendTG()` — только в запасном режиме и только для `severity = critical` и `trade_opened` / `trade_closed`; при переходе в этот режим — одно сообщение «бот не отвечает, пишу напрямую».
- Небольшой JSON-помощник на MQL5: сборка объектов строкой с экранированием `"`, `\`, переводов строки; числа — через `DoubleToString` с точкой; разбор команд — простой парсер плоского JSON (строки, числа, true/false) и одного вложенного `args`.
- Список событий, уровни и поля — раздел 6.

### 5.4 Настройки, меняющиеся из Telegram

- Входные параметры MQL5 — константы, поэтому ввести структуру `g_set`: `paused`, `riskPct`, `dailyRiskPct`, `maxTrades`, `rr`, `weak`, `tradeBuy`, `tradeSell`. В `OnInit` заполнить из входных параметров, затем наложить `settings.json`.
- Заменить чтение этих параметров на `g_set` везде: `Relaxed`, `GlobalBlock`, `TradeRiskPct`, `DailyRiskLeft`, `CalcLot`, `TryEntry` (тейк RR, стороны), `RebuildZones` (стороны), `OnPositionClosed`, `DrawPanel`, сообщения `OnInit`.
- Команда `reset` удаляет изменения и возвращает значения входных параметров. На панели изменённые из Telegram значения помечены «(TG)».

### 5.5 Пауза и автопауза

- Пауза останавливает только новые входы: `GlobalBlock` возвращает «пауза (Telegram)». Открытая позиция сопровождается как обычно: безубыток, ранний выход, закрытие в пятницу.
- Автопауза + критичная тревога: 3 отклонённых ордера подряд; позиция робота без стопа, которую не удалось исправить за 3 попытки. Снимается только командой `resume`.

### 5.6 События анализа

- `zone_touch`: цена впервые зашла в торгуемую зону CONFIRMED (флаг в `SZone`, один раз на зону).
- `signal_skipped`: триггер был (`EvalZone` = true), но вход заблокировал фильтр: балл, COUNTER, FVG, Doji / волчок, импульс, стоп больше максимума, RR, лот и риск, спред, новости, лимиты, пауза. Для этого `Skip(zi, why)` получает третий аргумент `hadSignal`. Повтор той же причины по той же зоне — не чаще раза в 30 минут (как сейчас).
- Пропуски без триггера («нет триггера») — событие `analysis_skip` уровня 2.
- `bias_changed` при смене D1 или H4; `zone_invalid` с причиной (уровень 2).

### 5.7 Скрины графика

- Когда: вход и выход (после отрисовки линий SL/TP), дневной отчёт, утренний брифинг, команда `chart`.
- M5 — график робота с зонами: `ChartRedraw()`, `ChartScreenShot(0, "MrCasino_shot.png", InpShotW, InpShotH, ALIGN_RIGHT)`, затем `FileMove("MrCasino_shot.png", 0, "MrCasino\\<robot>\\shots\\<seq>.png", FILE_COMMON | FILE_REWRITE)`.
- M15, H1, H4 — временный график `ChartOpen(sym, tf)`, на него копируются прямоугольники зон, скрин, `ChartClose`.
- Скрин не получился — событие уходит без фото, в `data.shot` пусто.

### 5.8 Тревоги, которые видит робот

Событие `alert` с полями `key` (ключ для склейки), `state` (`open` или `closed`), `severity` (`warning` или `critical`). Каждое состояние шлётся один раз при начале и один раз при окончании.

| key | Условие | Важность |
| --- | --- | --- |
| `disconnect` | `TERMINAL_CONNECTED` = false дольше 60 с | critical |
| `algo_off` | `TERMINAL_TRADE_ALLOWED` или `MQL_TRADE_ALLOWED` = false | critical |
| `no_sl` | позиция робота без стопа; робот пытается поставить стоп заново | critical |
| `orders_rejected` | 3 отказа подряд → автопауза; одиночный отказ — `order_rejected`, warning | critical |
| `day_dd` | эквити ниже баланса начала дня на `InpAlertDDPct` | warning |
| `day_limit` | дневной риск исчерпан, робот стоит до завтра | critical |
| `spread` | спред выше нормы в `InpAlertSpreadX` раз дольше 2 минут при открытой позиции | warning |
| `no_ticks` | нет тиков 5 минут, а торговая сессия символа открыта (`SymbolInfoSessionTrade`) | warning |
| `margin` | уровень маржи ниже 200% | warning |
| `friday_close` | позиция закрыта перед выходными | info |

### 5.9 Запуск, остановка, сделки

- `ea_started`: версия, счёт, символ, действующие настройки. `ea_stopped`: причина из `OnDeinit(reason)` по-русски (снят с графика, перекомпиляция, смена счёта, закрытие терминала и т.д.). Падение терминала события не даёт — его ловит сторож бота.
- Робот пишет закрытые сделки и в старый `MrCasino_v32_trades.csv`, и в `trades.csv` моста (новые колонки — раздел 10).
- Ручные сделки по команде `open` открываются с magic робота и комментарием `MC MANUAL`: робот ведёт их как свои (безубыток, пятница), в статистике они помечены `manual`.
- Панель: строка «Бот: онлайн / нет связи N мин» и «ПАУЗА (Telegram)», когда пауза включена.
- В `OnTick` — никаких `Sleep` и сетевых запросов; запись файлов — только при событиях и по таймеру.

## 6. События и сообщения

Робот пишет все события всех уровней; бот сам фильтрует по уровню, который выбрал владелец (`/level`). Уровень 0 — сделки, тревоги, отчёты, ответы на команды; 1 — плюс анализ (по умолчанию); 2 — всё.

| Тип | Уровень | Когда | Фото | Кнопки |
| --- | --- | --- | --- | --- |
| `trade_opened` | 0 | робот или команда `open` открыли сделку | да | График, Безубыток, Закрыть |
| `trade_be` | 0 | стоп перенесён в безубыток | нет | — |
| `trade_modified` | 0 | стоп или тейк изменены командой | нет | — |
| `trade_partial` | 0 | частичное закрытие | нет | — |
| `trade_closed` | 0 | выход: TP, SL, BE, EARLY, FRIDAY, MANUAL, OTHER | да | Сегодня, История |
| `limit_reached` | 0 | лимит сделок, дневного риска, серии стопов или цель дня | нет | Сегодня |
| `alert` | 0 | раздел 5.8 (начало и конец) | нет | Принял, Статус |
| `daily_report` | 0 | `InpReportHM` | да | История, Статистика |
| `morning_brief` | 0 | `InpMorningHM`, будни | да | Статус |
| `cmd_result` | 0 | ответ на команду | по команде `chart` | — |
| `ea_started`, `ea_stopped` | 0 | запуск и остановка робота | нет | Статус |
| `zone_confirmed` | 1 | новая зона CONFIRMED | нет | График |
| `zone_touch` | 1 | цена впервые в торгуемой зоне | нет | График |
| `signal_skipped` | 1 | триггер был, фильтр не пустил | нет | — |
| `bias_changed` | 1 | сменился bias D1 или H4 | нет | — |
| `zone_invalid`, `analysis_skip` | 2 | зона снята; пропуск без триггера | нет | — |

**Правила отправки:**

- Фото с подписью, если текст до 1024 символов; иначе фото, потом текст.

- Время в тексте — по Бишкеку; цены с точностью символа; деньги с 2 знаками и валютой счёта (USD, USC).
- Если роботов больше одного, первая строка начинается с метки счёта: сервер + 4 последние цифры логина.

Меню «Настройки» — инлайн-кнопки с текущими значениями и шагами (риск ±0.25%, день ±1%, сделки ±1, RR ±0.5, слабые, BUY, SELL, уровень, голос); каждое изменение робота идёт через «Да».

**Подтверждение:**

1. Бот пишет, что именно сделает, с цифрами «было → станет»: «Поставить риск 0.5% на сделку (сейчас 1%)?» + кнопки «Да» и «Нет».
2. Кнопки живут 60 секунд; потом сообщение меняется на «Время вышло». Каждое подтверждение одноразовое: второе нажатие ничего не делает.
3. После «Да» бот пишет команду с `expires_utc` = сейчас + 60 с и ждёт `cmd_result` до 15 с.
4. Ответ пришёл — сообщение меняется на «Готово: …» или «Не выполнено: …». Нет ответа — «Робот не ответил за 15 с: проверь MT5»; команда истечёт сама и позже не сработает.
5. Каждая команда и её результат пишутся в журнал действий (`/audit`).

Диапазоны в таблице защищают от опечатки (риск 50 вместо 0.5) и проверяются дважды: в боте и в роботе. Свободный текст и голосовые владельца на этапе 1 — ответ «Пока понимаю только кнопки и команды, /help»; на этапе 2 их разбирает «Жарвис».

## 9. Сторож, тревоги, голосовые

Критичная тревога приходит текстом и голосовым сразу и повторяется каждые 2 минуты, пока владелец не нажмёт «Принял» или причина не уйдёт. Сторож работает в боте и ловит то, чего робот сам не скажет: закрытый или зависший MT5. Проверка каждые 10 с.

| Проверка | Условие | Важность | Действие |
| --- | --- | --- | --- |
| MT5 закрыт | процесса `terminal64.exe` нет дольше 30 с | critical | автоперезапуск из `MT5_PATH`: не чаще 1 раза в 10 минут и 3 раз в час; о результате — сообщение |
| Робот молчит | MT5 работает, а `status.json` старше 60 с | critical | «MT5 завис или робот снят с графика» |
| Тревоги робота | события `alert` из раздела 5.8 | по событию | показать, озвучить, закрыть при `state = closed` |
| Интернет ПК пропадал | бот не мог отправить дольше 2 минут | warning | после восстановления: «связи не было с 14:10 до 14:25» + задержанные события |
| Диск | свободно меньше 1 ГБ | warning | сообщение раз в сутки |
| Выходные | рынок закрыт (`status.symbol.market_open = false`) | — | тревоги «нет тиков» и «нет связи» не шлются |

**Эскалация:**

- critical: текст + голосовое сразу; повтор каждые 2 минуты до «Принял», максимум 10 раз, дальше напоминание раз в час.
- warning: текст один раз; если держится дольше 30 минут — повтор.
- «Принял» останавливает повторы этой тревоги, но не скрывает её окончание: «✅ Восстановлено…» приходит всегда.
- Тревоги не глушатся ни `/mute`, ни тихими часами.

**Голосовые:**

- Озвучка `edge-tts` (бесплатно, нужен интернет), голос из `VOICE`: `ru-RU-DmitryNeural` или `ru-RU-SvetlanaNeural`. Отправка через `sendVoice`.
- Фраза короткая, до 20 секунд, с именем из `OWNER_NAME`: «Абу, тревога. Робот потерял связь с брокером три минуты назад. Позиция открыта, стоп стоит». Для сделок: «Вход в покупку по золоту, стоп пять с половиной пункта, риск один процент».
- Что озвучивается: все critical — всегда; входы и выходы — при `VOICE_TRADES=true` или `/voice on`; дневной отчёт — нет.
- Озвучка не сработала — уходит только текст с пометкой «голос недоступен». Одинаковые фразы кэшируются файлами.

**Ограничение iPhone:** Telegram не может пробить беззвучный режим и режим «Не беспокоить». Чтобы тревогу заметили: отдельный громкий звук для чата бота в настройках Telegram, Telegram в исключениях режима фокусировки iPhone, повтор до «Принял». Настоящий звонок — в бэклоге (раздел 15).

## 11. Безопасность

Управлять счётом может только владелец и только свежей подтверждённой командой; защита стоит и в боте, и в роботе.

- **Только владелец:** каждое сообщение и нажатие кнопки проверяется `from_user.id == OWNER_ID`. Чужой получает «Доступ закрыт»; попытка пишется в лог, владелец получает одно уведомление в сутки на каждого чужого. Группы и каналы бот игнорирует.
- **Токен бота:** только в `.env` на ПК; не в репозитории, не в логах, не в чатах. Утёк — в @BotFather `/revoke`, новый токен в `.env`.
- **Ключ моста:** одинаковый секрет в `InpBridgeKey` робота и `BRIDGE_KEY` бота, 32+ случайных символа (`install.bat` генерирует и показывает). Команду без верного ключа робот отклоняет: другие программы на ПК не смогут управлять им через файлы.
- **Свежесть:** кнопки «Да» живут 60 с и одноразовы; команда с истёкшим `expires_utc` не выполняется — например, после сна ПК старое «закрыть» не сработает.
- **Двойная проверка:** диапазоны и состояние (есть ли позиция, сторона стопа, стоп-уровень брокера) проверяет и бот, и робот — ошибка в боте не превратится в плохую сделку.
- **Жёсткие правила робота остаются при любых командах:** стоп обязателен, одна позиция, дневной лимит убытка, закрытие перед выходными. Изменить лимит можно только командой с «Да».
- **Журнал действий:** каждая команда и результат в таблице `audit`, просмотр — `/audit`.
- **Сеть:** long polling, без webhook и открытых портов; бот работает под обычной учётной записью Windows, без прав администратора.

## 12. Установка и автозапуск на Windows

Установка занимает около часа один раз; потом ПК после включения сам запускает MT5 с роботом и бота. Эти же шаги — в `tg_bot/README.md`.

1. **MT5 для ПК.** Скачать с сайта своего брокера (Exness или XM), установить, войти в счёт. Для старта — демо.
2. **Разрешения.** Сервис → Настройки → Советники: включить «Разрешить алгоритмическую торговлю». Для запасного канала — «Разрешить WebRequest для URL» и добавить `https://api.telegram.org`.
3. **Робот.** Файл → Открыть каталог данных → `MQL5\Experts` → положить `MrCasino.mq5` → открыть в MetaEditor → F7 → 0 ошибок.
4. **График.** Открыть золото (`XAUUSDm` или `GOLD#`) M5, перетащить робота, во входных параметрах вписать `InpBridgeKey`, остальное по умолчанию. Кнопка «Алго-торговля» зелёная.
5. **Профиль.** Файл → Профили → Сохранить как…: после перезапуска MT5 сам откроет график с роботом.
6. **Python 3.12** с python.org, галочка «Add python.exe to PATH».
7. **Бот.** Скачать репозиторий (ZIP с GitHub или `git clone`), открыть папку `tg_bot`, запустить `install.bat`: создаёт venv, ставит зависимости, при необходимости ffmpeg через `winget`, генерирует `BRIDGE_KEY` и создаёт `.env` из `.env.example`.
8. **Telegram.** В @BotFather `/newbot` → токен; в @userinfobot → свой ID. Вписать в `.env`: `BOT_TOKEN`, `OWNER_ID`, `MT5_PATH`; `BRIDGE_KEY` скопировать в параметр робота из шага 4.
9. **Проверка.** `start_bot.bat` → в Telegram `/start` → `/test`: приходят текст, голосовое и «робот ответил».
10. **Автозапуск бота.** Планировщик заданий → задача «При входе в систему» → `start_bot.bat` (скрытое окно, перезапуск при сбое). `start_bot.bat` сам перезапускает бота через 10 с после падения. `install.bat` умеет создать эту задачу через `schtasks`.
11. **Автозапуск MT5.** Ярлык `terminal64.exe` в папке `shell:startup`.
12. **Электропитание.** Сон: никогда (экран можно выключать). Windows Update: активные часы 08:00–02:00, чтобы не перезагружался в сессию.
13. **По желанию.** Автовход в Windows (`netplwiz`) и в BIOS «включаться при появлении питания»: после отключения света всё поднимется само. Автовход снижает защиту ПК — решает владелец.
