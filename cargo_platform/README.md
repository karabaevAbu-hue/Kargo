# Карго-конструктор ботов — неделя 1

Одна программа держит главный бот платформы и боты всех карго-компаний.
Карго регистрируется в главном боте, присылает токен своего бота, проходит
мастер настройки — и его бот сразу работает. Подробно — в ТЗ.

## Что готово (всё MVP из ТЗ, разделы 1–11)

**Главный бот (владелец карго и Абу)**
- Регистрация карго, проверка полей, подключение и смена токена, мастер настройки из 13 шагов,
  правка любого поля, приветствие клиента, переключатели (город / адрес доставки при регистрации клиента,
  уведомления о статусах «Склад Китая» и «Отправлено»).
- При смене бота клиентам старого бота уходит ссылка на новый.
- Менеджеры по одноразовой ссылке на 24 часа, лимиты менеджеров и клиентов по тарифам.
- Подписки: напоминание за 3 дня и в день окончания, 3 льготных дня, потом пауза.
- «Платформа» (Абу): список карго, `/extend`, `/block`, `/unblock`, статистика (только количества),
  журнал ошибок ботов, `/purge ID` — удаление данных ушедшего карго через 90 дней.

**Клиентский бот (русский и кыргызский)**
- Регистрация: язык, имя, телефон (кнопкой или текстом), поля карго, согласие с правилами; код выдаётся атомарно.
- Готовый адрес склада: получатель, телефон и адрес отдельными сообщениями, инструкция, QR для выдачи.
- Меню: трек-номера (по одному или списком, дубли, чужие треки), «Мои посылки» с фильтрами, «К оплате»,
  оплата QR + фото чека, калькулятор, тарифы и сроки, запрещённые товары, адрес ПВЗ, связь с менеджером, профиль.
- Поиск по трек-номеру без регистрации (только статус).

**Админка менеджера (`/admin`)**
- Партии: загрузка Excel (.xlsx/.xls/.csv), выбор колонок, шаблон склада, отчёт до сохранения,
  «Отправлено из Китая» (с датой прибытия), «Прибыла на ПВЗ».
- Приёмка с телефона: код или трек (в том числе фото штрихкода), вес, габариты, сумма сразу.
- Выдача: по коду или QR, выбор посылок, наличные, «ждать перевод», выдача в долг (с записью в журнал).
- Подтверждение чеков: полностью, частично, отказ с причиной, предупреждение о повторном чеке.
- Клиенты (поиск, карточка, блокировка, индивидуальная цена, отвязка Telegram, смена телефона),
  посылки (вес, статус, перенос другому клиенту, проблема), «Неопознанные», должники, сообщения клиентов.
- Рассылки (все / партия / должники / город, кнопка-ссылка, «на время»), отчёты день/неделя/месяц с Excel,
  журнал действий, выгрузка всех данных.

**Автоматика:** уведомления о каждом шаге, напоминания об оплате (через 2 и 5 дней), предупреждение о конце
бесплатного хранения, платное хранение, отчёт дня владельцу в 20:00, лимит 25 сообщений/сек на бота,
рассылки продолжаются после перезапуска сервера.

## Структура

```
cargo_platform/
  main.py                  # запуск сервера
  config.py                # настройки из .env
  texts.py                 # тексты главного бота ru / ky
  db/models.py             # таблицы
  master_bot/              # главный бот: регистрация, настройки, меню, «Платформа»
  client_bot/              # бот карго для клиентов (texts.py — тексты ru / ky)
  admin_bot/               # админка менеджера внутри бота карго
  services/                # расчёт, коды, Excel, посылки и долг, уведомления, рассылки, отчёты, фоновые задачи
  tools/                   # genkey, monitor, backup.sh, restore_test.sh
  tests/                   # test_week1, test_full, run_all
```

## Запуск на MacBook (для теста)

Telegram отправляет обновления только на HTTPS-адрес, поэтому на ноутбуке
нужен туннель. Проще всего — cloudflared.

```bash
# 1. Папка проекта: положите cargo_platform в любую папку, например ~/cargo
cd ~/cargo
python3 -m venv venv && source venv/bin/activate
pip install -r cargo_platform/requirements.txt

# 2. Ключ шифрования
python -m cargo_platform.tools.genkey      # скопируйте строку в FERNET_KEY

# 3. Туннель (в отдельном окне терминала)
brew install cloudflared
cloudflared tunnel --url http://localhost:8080
#   он покажет адрес вида https://xxxx.trycloudflare.com → это BASE_URL

# 4. Настройки
cp cargo_platform/.env.example cargo_platform/.env
#   заполните MASTER_BOT_TOKEN, BASE_URL, FERNET_KEY, MASTER_WEBHOOK_SECRET, PLATFORM_ADMINS

# 5. Запуск
python -m cargo_platform.main
```

Адрес trycloudflare меняется при каждом запуске туннеля: обновите BASE_URL и
перезапустите программу, она сама переставит webhook всех ботов.

## Проверка

```bash
python -m cargo_platform.tests.run_all     # 185 проверок без Telegram
```

`test_full` проходит весь цикл: регистрация клиента → трек → Excel склада → отправка и прибытие партии →
оплата (полная, частичная, отказ, наличные) → выдача → правка веса → неопознанные → рассылка → отчёты →
пауза за неоплату → напоминания → смена бота → изоляция двух карго.

## Запуск на сервере (VPS, Ubuntu)

1. VPS от 2 ГБ RAM, домен, направленный на сервер.
2. Установить Docker и nginx (или Caddy) с HTTPS от Let's Encrypt,
   проксировать `https://домен` → `http://127.0.0.1:8080`.
3. Скопировать папку `cargo_platform` на сервер, заполнить `.env`
   (BASE_URL = `https://домен`, задать POSTGRES_PASSWORD).
4. `docker compose up -d --build`
5. Проверка: `curl https://домен/health` → `ok`.

**Бэкап каждую ночь** (`crontab -e`):

```
0 3 * * * RCLONE_REMOTE=gdrive:cargo-backups /путь/cargo_platform/tools/backup.sh >> /var/log/cargo_backup.log 2>&1
```

Скрипт делает `pg_dump`, хранит 14 дней и копирует файл в отдельное облако через rclone
(`rclone config` один раз). Без `RCLONE_REMOTE` он предупредит, что копия лежит только на сервере.
**Раз в месяц** запускайте `tools/restore_test.sh`: он восстанавливает последний бэкап во временную базу
и показывает, сколько в нём карго и клиентов.

**Мониторинг:** контейнер `monitor` раз в 5 минут проверяет `/health` и при падении пишет Абу в Telegram.

## Важно

- `FERNET_KEY` не терять и не менять: без него токены ботов не расшифровать.
- Файл `.env` никогда не загружать в GitHub.
- Состояния диалогов пока в памяти: при перезапуске человек, который был
  посреди регистрации, начнёт шаг заново через /start. При росте — Redis.
- Таблицы создаются через `create_all`. В этой версии добавились таблицы и колонки (`notice_log`, `error_log`,
  `use_china_statuses`, `problem_note`, `broadcasts.created_at`): базу первой недели пересоздайте (боевых данных
  там ещё нет). Миграции Alembic из ТЗ ещё не подключены — подключить до первого живого карго.
- Кыргызский перевод — черновик, дайте проверить носителю. Админка менеджера только на русском.
- Чтение штрихкодов по фото требует `libzbar0` (в Docker-образе есть); без него бот просит ввести значение вручную.

## Решения, которых ТЗ не фиксирует (поменять легко)

- Платное хранение считается раз на клиента и партию от самой ранней неполученной посылки.
- Долг = начисления − подтверждённые платежи; переплата (отрицательный долг) уходит в следующее начисление.
- Строки одного трека внутри одного файла сливаются в одну посылку (места и вес суммируются);
  трек, принятый раньше, — дубль и повторно не начисляется.
- Если код в файле неверный, но трек добавлен клиентом, посылка привязывается по треку.
- «Выдать в долг» есть, но пишется в журнал отдельным действием.
- Регистрация клиента спрашивает город только если включено в настройках; ПВЗ один (вопрос про несколько — в разделе 12 ТЗ).
